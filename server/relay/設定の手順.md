# 不具合・要望の中継役（Cloudflare Workers）の設定の手順

アプリから届いた報告を、GitHub の Issue（`Tocoroten3391/Sekigae-Shitaro_Apps`）にする「中継役」を、Cloudflare に置きます。
かかる時間は、30分ほどです。お金は、かかりません（無料の範囲で足ります）。

```
アプリ → 中継役（Cloudflare Workers）→ GitHub の Issue
              ↑ GitHub のトークンは、ここだけが持つ
```

## 1. GitHub のトークンを作る（Issue を作るだけの鍵）

1. GitHub にログインして、右上の自分のアイコン →「Settings」→ 左の一番下「Developer settings」
2. 「Personal access tokens」→「Fine-grained tokens」→「Generate new token」
3. 次のように入れます。
   - Token name：`sekigae-feedback`
   - Expiration：1年（切れる日を、カレンダーに入れておく）
   - Repository access：**Only select repositories** →「Sekigae-Shitaro_Apps」だけ
   - Permissions →「Repository permissions」→ **Issues：Read and write**（ほかは、すべて「No access」のまま。Metadata は、自動で Read-only になります）
4. 「Generate token」を押して、出てきた `github_pat_…` を、**コピーしておく**（二度と表示されません）

> このトークンでできるのは、「Sekigae-Shitaro_Apps」の Issue を、読み書きすることだけです。コードの書き換えは、できません。

## 2. Cloudflare のアカウントを作る

1. <https://dash.cloudflare.com/sign-up> でアカウントを作ります（メールアドレスと、パスワード）
2. 届いたメールで、確認します

## 3. 中継役（Worker）を作る

1. 左のメニュー「Workers & Pages」→「Create」→「Create Worker」
2. 名前を `sekigae-feedback` にして「Deploy」
3. 「Edit code」を押す
4. 左のファイル `worker.js` の中身を、**すべて消して**、同じフォルダの `worker.js` の中身を、**すべて貼り付け**ます
5. 右上の「Deploy」を押す

## 4. 設定を入れる

作った Worker の画面で「Settings」→「Variables and Secrets」→「Add」

| 種類 | 名前 | 値 |
|---|---|---|
| Text | `GH_OWNER` | `Tocoroten3391` |
| Text | `GH_REPO` | `Sekigae-Shitaro_Apps` |
| **Secret** | `GH_TOKEN` | 手順1でコピーした `github_pat_…` |

入れたら「Deploy」を押します。

## 5. 保管場所（KV）をつなぐ（スクリーンショットを付けるときは、必ず必要です）

KV は、Cloudflare の「メモ帳」です。2つの役目があります。
- 荒らされないよう、1つの接続元から、1時間に20件までにする（回数の制限）
- 報告に付けた**スクリーンショットを、180日だけ置いておく**（GitHub には、置きません）

1. 左のメニュー「Storage & Databases」→「KV」→「Create」→ 名前 `sekigae-rate`
2. Worker の画面「Settings」→「Bindings」→「Add」→「KV namespace」
3. Variable name：`RATE`、KV namespace：`sekigae-rate` →「Deploy」

> 入れなくても、文章の報告は送れます。ただし、スクリーンショットは付かず、回数の制限も、あまり効かなくなります。
> 画像は、リンクを知っている人なら見られます（Issue が公開なので、同じことです）。消したいときは、KV の画面で、`img:` で始まるキーを消します。

## 6. 動くか確かめる

1. Worker の画面に出ている URL（`https://sekigae-feedback.〇〇.workers.dev`）を、ブラウザで開く
2. `{"ok":true,"name":"sekigae-feedback-relay"}` と出れば、成功です

## 7. アプリに、URL を教える

手順6の URL を、Claude に教えてください。アプリに組み込んで、次の版で配ります。

## 困ったとき

| 症状 | 原因・対処 |
|---|---|
| アプリで「受け付けられませんでした（F-SRV／github_401）」 | トークンが違う、または期限切れです。手順1を、やり直して、`GH_TOKEN` を入れ直す |
| 「github_403」「github_404」 | トークンに、Issue の権限がない、またはリポジトリの指定が違います。手順1の「Issues：Read and write」と、`GH_OWNER`／`GH_REPO` を確認 |
| 「github_422」 | ラベルの名前が違うなど。Apps リポジトリのラベル（不具合・要望・質問・アプリから）があるか確認 |
| 「not_configured」 | `GH_TOKEN`／`GH_OWNER`／`GH_REPO` のどれかが、入っていません |
| 「画像は、付けられませんでした（F-IMG／no_store）」 | KV が、つながっていません。手順5をやる |
| 「F-IMG／bad_image」 | 画像が大きすぎる、またはJPEGではありません。アプリが縮めるので、ふつうは起きません。もう一度、選び直す |
| 荒らされた | Worker の画面で「Settings」→「Domains & Routes」の `workers.dev` を無効にすると、すぐ止まります。トークンを GitHub で「Delete」すれば、Issue は作られなくなります |

## 知っておくこと
- 報告は、**公開の Issue** になります。アプリの画面に、そう書いてあります。
- スクリーンショットは、アプリの中で、縮めて、JPEGにしてから送られます（撮影した場所などの情報は、消えます）。画面の「隠す」で、名前などを黒く塗ってから送れます。1件に、3枚までです。
- 中継役のコード（`worker.js`）が新しくなったときは、手順3の4〜5と同じように、`worker.js` を貼り直して「Deploy」を押します。変数・シークレット・KV は、そのまま残ります。
- トークンの期限が切れる前に、手順1を、やり直して、`GH_TOKEN` を入れ直します。
- 1日に作る Issue は、全体で100件までにしてあります（`worker.js` の `LIMIT_PER_DAY`）。
- アプリの「送った報告」は、中継役の `/status` から、報告の状況（受付中・対応済み・見送り）と、管理者の返信を受け取ります（ブラウザで `https://sekigae-feedback.〇〇.workers.dev/status?n=4` を開くと、中身が見られます）。`worker.js` を古いままにしておくと、アプリは GitHub に直接聞きますが、返信の文章は出ません。
- 返信として出るのは、リポジトリの持ち主・メンバー・共同作業者のコメントだけです。ほかの人のコメントは出しません。
